# 시간대별 조도(lux) 예측

10분 간격으로 기록된 조도 데이터로 **"어제까지의 데이터로 오늘 0~23시 조도를 예측"** 하는
모델 5종을 만들고, 첫 4주 이후 하루씩 전진하는 rolling-origin 방식으로 평가한다.

- `forecast.py`: 전처리, 입력 X 생성, 모델, 순차 검증, 지표 계산 (실행 스크립트)
- `plots.py`: 결과 그림
- `test_forecast.py`: 시간 집계·피처 정의·미래 데이터 누출 여부 테스트 (합성 데이터)

## 실행

```bash
pip install -r light_forecast/requirements.txt
python light_forecast/forecast.py --csv path/to/lux.csv --out outputs
python -m pytest light_forecast            # 테스트
```

입력 CSV는 첫 열이 timestamp, 둘째 열이 조도(lux)이다. 옵션:

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--min-readings` | 1 | 시간값을 만들 때 필요한 최소 10분 측정 수 |
| `--ridge-alpha-rule` | `min` | Ridge alpha 선택 규칙. `min`=CV 최소 오차, `1se`=1-SE 규칙(민감도 분석) |
| `--no-plots` | | 그림 생략 |

`--out` 폴더에 생기는 파일:

| 파일 | 내용 |
|---|---|
| `predictions_{mean,median}.csv` | 평가일·시각별 5개 모델의 고정된 예측값과 실측 |
| `metrics.csv` | 모델별 MAE·RMSE (평가 부분집합별) |
| `bootstrap_vs_reference.csv` | 모델 간 오차 차이와 95% 신뢰구간 |
| `mae_by_hour_*.csv`, `mae_by_date_*.csv` | 시각별·날짜별 MAE |
| `next_day_forecast_*.csv` | 마지막 관측일 다음 날의 0~23시 예측 ("실제 예측") |
| `figures/*.png` | 그림 |

개인 건강 데이터이므로 원본 CSV와 `outputs/`는 저장소에 올리지 않는다(`.gitignore`).

## 방법

### 1. 전처리

1. 같은 timestamp의 중복 행을 하나로 합친다(값이 다르면 평균).
2. 10분 측정치마다 `log(lux+1)`를 구하고, 시간(0~23시)별로 **평균**을 낸다. 비교군으로
   같은 값의 **중앙값**으로 만든 시간 조도로 전체 과정을 한 번 더 수행한다.
3. 측정이 없는 날짜·시간을 NaN으로 둔 **연속 달력(날짜 x 24시간)** 을 만든다.
   "어제", "지난주 같은 요일", "최근 7일"은 모두 달력 기준이다(관측일 기준이 아님).

### 2. 모델

| 모델 | 예측값 | 과거 값이 없으면 |
|---|---|---|
| B1 어제 값 | D-1일 h시 | 예측 불가 |
| B2 지난주 같은 요일 | D-7일 h시 | 예측 불가 |
| B3 최근 7일 중앙값 | D-7 ~ D-1일 h시 값 중 관측된 값의 중앙값 | 7일 모두 없을 때만 예측 불가 |
| B4 평일·휴일 구분 | 평일 D-1일, 휴일(토·일) D-7일 h시 | 예측 불가 |
| Ridge | 아래 입력 X로 학습 | 항상 예측 |
| LightGBM | 아래 입력 X로 학습 | 항상 예측 |

Ridge와 LightGBM은 시각별로 따로 두지 않고 모든 시각을 하나의 모델로 학습한다(시각은 입력 X에 포함).

### 3. 입력 X와 정답 y (예측 대상 날짜 D, 시각 h)

| 입력 | 정의 |
|---|---|
| `lag_1` ~ `lag_7` | 이전 7일(D-1 ~ D-7일)의 같은 시각 조도 |
| `hist_mean`, `hist_std` | D-1일까지 전체 과거의 같은 시각 조도 평균·표준편차 |
| `seg_morning`, `seg_afternoon`, `seg_evening` | 최근 날짜의 오전(06~12시)·오후(12~18시)·저녁(18~24시) 평균 조도. D-1일을 우선 쓰고, 그 구간이 비었으면 7일 이내 가장 최근 관측일 값을 쓴다(구간 6시간 중 3시간 이상 관측된 날만 인정) |
| `hour`, `weekday` | 예측 대상의 시각·요일 |

**정답 y** = D일 h시의 실제 조도(`log(lux+1)` 척도).

학습 사례는 (날짜, 시각) 쌍이다. 오전 10시만 떼어 보면 다음과 같다.

| 구분 | 입력 X 중 lag 부분 | 정답 y |
|---|---|---|
| 학습 사례 1 | 1~7일째의 10시 조도 7개 | 8일째 10시 실측 |
| 학습 사례 2 | 2~8일째의 10시 조도 7개 | 9일째 10시 실측 |
| ... | ... | ... |
| 학습 사례 21 | 21~27일째의 10시 조도 7개 | 28일째 10시 실측 |
| 실제 예측 | 22~28일째의 10시 조도 7개 | 29일째 10시 추정 |

결측 처리: LightGBM은 NaN을 그대로 입력한다. Ridge는 빈 lag를 같은 시각의 `hist_mean`으로
채우고 lag별 결측 지시변수를 추가하며, 나머지 결측은 학습 구간 평균으로 채운다. 시각·요일은
원-핫으로 넣는다. Ridge의 alpha는 학습 구간 안에서 **날짜 단위 GroupKFold(5-fold)** 로 고른다
(같은 날 24개 행이 날짜 단위 피처를 공유하므로 행 단위 LOO는 alpha를 과소 선택한다).
LightGBM 하이퍼파라미터는 평가 결과를 보고 조정하지 않도록 작은 표본용 보수적 값으로 고정했다.

### 4. 평가: 첫 4주 이후 일 단위 순차 검증 (rolling-origin)

1. 데이터 첫날부터 4주(28일)를 초기 학습 구간으로 둔다.
2. 그다음 날 D부터 하루씩 전진하며,
   - D 이전 관측만 남긴 데이터로 학습 사례를 새로 만들고 모델을 다시 학습한다(expanding window).
   - D의 0~23시 예측값을 **먼저 고정**한다.
   - D의 실측을 공개한 뒤 오차를 계산한다. 이후 D의 실측은 D+1일 예측부터 학습에 들어간다.
3. 예측 시점 이후 관측은 학습에 쓰지 않는다. `forecast_day()`는 D 이후 데이터를 잘라낸 뒤
   피처를 만들며, 테스트에서 D일과 이후 값을 바꾸거나 지워도 D일 예측이 같음을 확인한다.

지표는 `log(lux+1)` 척도의 MAE·RMSE(보조로 lux 척도 MAE). B1·B2는 과거 값이 없으면 예측할 수
없으므로 다음 부분집합으로 나눠 **같은 시각끼리** 비교한다.

| 부분집합 | 의미 |
|---|---|
| `common` | 다섯 모델이 모두 예측 가능한 시각 (다섯 모델 공정 비교) |
| `yesterday_observed` / `yesterday_missing` | 어제 같은 시각 값이 있는/없는 시각 |
| `all` | 실측이 있는 모든 시각 (B1·B2는 예측 가능한 시각만, coverage 표시) |

모델 간 차이의 불확실성은 평가일을 복원추출하는 블록 부트스트랩(5,000회)으로 95% 구간을 구한다.

## 결과 (예시 데이터 1명, 2026-06-26 ~ 2026-09-20)

**데이터**: 4,717행 중 중복 timestamp 236행(값 동일)을 합쳐 측정치 4,481개. 달력 87일 중 52일에만
측정이 있고, 2,088개 시간 칸 중 800개(38%)만 관측됐다. 초기 학습 구간은 06-26 ~ 07-23,
평가 구간은 07-24 ~ 09-20(59일 예측, 그중 실측이 있는 35일·626시간을 채점)이다.
학습 사례는 161개에서 780개로 늘었다. 아래 값은 모두 `log(lux+1)` 척도이다.

### 해석

1. **어제 값이 있으면 B1(어제 값 그대로)이 MAE 기준 가장 정확하다.** Ridge·LightGBM보다 MAE가
   약 0.23~0.25 낮고, 신뢰구간 하한이 0 근처라 경계선 수준의 차이이다.
2. **RMSE 기준으로는 Ridge·LightGBM이 B1과 비슷하고 B2·B3보다 낮다.** 학습 모델은 제곱오차로
   학습돼, 기상·소등 시각처럼 켜짐/꺼짐이 불확실한 시각에 중간값을 내놓는다. 크게 틀리는 경우는
   줄지만 MAE에서는 불리하다. B1은 맞으면 오차가 0에 가깝고 틀리면 크게 틀린다.
3. **어제 값이 없는 시각**에서는 MAE는 B3, RMSE는 LightGBM이 가장 낮다. 전체 626시간에서
   LightGBM은 MAE로는 B3와 같고(+0.009), RMSE로는 낮다(-0.278, 구간 상한 0.01로 경계선).
4. **Ridge는 LightGBM보다 약하다.** 선형 모델에서는 날짜 단위 피처(최근 구간 평균)가 24시간
   전체를 같은 폭으로 움직여, 전날 저녁이 밝았으면 밤 시간 예측까지 올라간다(0~5시 MAE:
   Ridge 0.77, LightGBM 0.50, B3 0.36). 트리 모델은 시각과의 상호작용을 스스로 학습한다.
5. **평균 집계와 중앙값 집계는 결론이 같다.** 모델 순위가 같고 MAE 차이는 0.05 이하이다.
6. 관측이 38%뿐이고 채점된 평가일이 35일이라 대부분의 차이는 통계적으로 유의하지 않다.

**민감도 (Ridge alpha 선택 규칙)**: `--ridge-alpha-rule 1se`로 1-SE 규칙을 쓰면 alpha가 31~1000
범위로 안정되지만 `lag_1` 계수가 더 줄어, 공통셋 MAE 0.924 → 1.099, 전체 MAE 1.155 → 1.201
(RMSE 1.674 → 1.648)이 된다. Ridge 성능은 규제 강도에 민감하지만 위 결론은 바뀌지 않는다.

### 추가 실험: 평일/휴일 구분 (평균 집계)

평일과 휴일(토·일)의 조도 패턴이 다를 수 있다는 가정으로 다음 세 모델을 추가했다.
기존 모델과 같은 학습 사례·같은 순차 검증으로 학습해 같은 시각끼리 비교한다.

- **B4_daytype**: 평일은 어제 값, 휴일은 지난주 같은 요일(토→지난 토, 일→지난 일) 값.
  월요일의 "어제"는 일요일이다.
- **Ridge_daytype / LightGBM_daytype**: 기존 입력 X에 `is_weekend`와 `daytype_ref`
  (평일이면 lag_1, 휴일이면 lag_7)를 추가.

| 비교 (MAE / RMSE) | 평일 | 휴일 | 전체 |
|---|---|---|---|
| 공통셋 시각 수 | 51 | 183 | 234 |
| B1 어제 값 | 0.785 / 1.513 | **0.671** / 1.487 | **0.696** / 1.493 |
| B4 평일·휴일 구분 | 0.785 / 1.513 (B1과 동일) | 1.297 / 2.147 | 1.186 / 2.026 |
| LightGBM → +구분 | 0.895 → 0.854 | 1.007 → 0.907 | 0.983 → 0.895 / 1.460 → **1.392** |
| Ridge → +구분 | 1.087 → 1.052 | 0.879 → 0.965 | 0.924 → 0.984 |

같은 시각에서의 차이와 평가일 블록 부트스트랩 95% 구간 (실측이 있는 모든 시각):

| 비교 | 평일 MAE 차이 | 휴일 MAE 차이 | 전체 MAE 차이 |
|---|---|---|---|
| B4 - B1 | 0 (동일) | +0.626 [0.05, 1.29] | +0.379 [0.01, 0.81] |
| LightGBM_daytype - LightGBM | +0.024 [-0.01, 0.05] | **-0.079 [-0.13, -0.03]** | -0.028 [-0.07, 0.01] |
| Ridge_daytype - Ridge | -0.032 [-0.09, 0.03] | +0.070 [-0.01, 0.16] | +0.020 [-0.03, 0.08] |

- 단순 대체 규칙에서는 **휴일에도 지난주 같은 요일보다 어제 값이 훨씬 정확하다**(토 0.99 vs 1.43,
  일 0.35 vs 1.17). 이 데이터에서는 요일 주기보다 전날과의 연속성이 강하다.
- LightGBM은 구분 정보를 넣으면 휴일 오차가 유의하게 줄어(MAE -0.079) 공통셋 MAE 0.895,
  RMSE 1.392로 학습 모델 중 가장 좋다. 평일은 차이가 거의 없다.
- Ridge는 개선되지 않는다(휴일에서 오히려 +0.070, 유의하지 않음).

### 여러 사용자 평가 (`multi_user.py`)

```bash
python light_forecast/multi_user.py --xlsx path/to/light_all.xlsx --out outputs/multi_user
```

시트마다 한 사용자(`timestamp`, `value` 열, 5분 간격)이며, 사용자마다 독립적으로 위와 같은
전처리(log(lux+1) 시간 평균)·8개 모델·첫 4주 이후 일 단위 순차 검증을 적용한다. 실측이 없는 날은
채점할 수 없으므로 예측을 생략하고, 학습일이 5일 미만인 시점에는 학습 모델이 예측하지 않는다.

예시 데이터 25명 중 4명은 기간이 4주 이하, 1명은 평가일이 2일뿐이라 제외하고 평가일 10일 이상인
20명을 요약했다. 사용자별 MAE를 모아 평균을 내고(사용자당 1표), B3 대비 차이를 Wilcoxon
부호순위 검정으로 본다. 공통셋(사용자별로 모든 모델이 예측 가능한 시각) 기준:

| 모델 | 평균 MAE | 평균 RMSE | MAE 순위 평균 | B3보다 MAE 낮은 사용자 | B3보다 RMSE 낮은 사용자 |
|---|---|---|---|---|---|
| B1 어제 값 | 1.351 | 1.996 | 5.98 | 3/20 | 1/20 |
| B2 지난주 같은 요일 | 1.481 | 2.141 | 6.85 | 2/20 | 1/20 |
| B3 최근 7일 중앙값 | 1.178 | 1.730 | 3.45 | - | - |
| B4 평일·휴일 구분 | 1.362 | 2.006 | 6.28 | 3/20 | 1/20 |
| Ridge | 1.240 | 1.578 | 3.95 | 10/20 | 19/20 |
| LightGBM | **1.167** | **1.557** | 2.85 | 10/20 | 18/20 |

  사용자별 부트스트랩에서도 RMSE는 18명에서 유의하게 낮고, 유의하게 높은 사용자는 없다.

### 추가 실험: 일출·일몰 기준 4구간의 7일 평균 (`--segments sun7d`)

| 모델 | MAE 기존 → 4구간 7일 | RMSE 기존 → 4구간 7일 | MAE 개선 사용자 | 사용자별 유의 차이 |

### 한계와 개선 방향

- 결측이 많아 B1은 평가 시각의 49%, B2는 35%에서 예측할 수 없다.
- 평가 구간에 하루 종일 0~2 lux로 기록된 날이 2일 있다. 비착용이나 센서 가림이 의심되며 모든 모델의 큰 오차 원인이다.
  걸음 수·심박 등으로 착용 여부를 판단해 제외하는 전처리를 검토할 만하다.
- 개선 후보(평가 결과를 본 뒤 떠올린 것이므로 새 데이터로 검증 필요):
  - 어제 값이 있으면 B1, 없으면 B3 또는 LightGBM을 쓰는 조합. 같은 626시간에서 사후 계산하면
    B1→B3가 MAE 0.926 / RMSE 1.632, B1→LightGBM이 MAE 0.963 / RMSE 1.551이다.

  - MAE가 주 지표라면 LightGBM의 목적함수를 L1으로 변경.
  - Ridge에 날짜 단위 피처 x 시간대 상호작용 추가.
